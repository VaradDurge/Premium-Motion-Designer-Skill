# Product films

## Pick the structure from the job

**Launch.** A person is doing the thing the product is for. The problem becomes a specific state or a single number. The mechanism is shown, large. One proof lands. A sentence states the claim. The brand closes, smaller than the claim.

**Demo.** Fewer posters, more product. A cursor or a state change causes a visible result. Crop to the component that changed. Do not tour the whole app.

**Explainer.** One diagram or one world. Each scene adds exactly one idea. UI drawn inside that world has to share its material.

**Ad variant.** Same system as the film. Change the first beat only: pain, result, or offer. Recompose for 9:16 and 1:1. Do not restage the film per format.

**Showreel.** Poster rules: one idea per frame, one motif, a lockup. No fake product UI. Do not use this structure for a launch.

## A 30-second launch, in frames

At 30fps. This is a budget, not a plot. Replace the events with this product's real states.

| Frames | Seconds | What the viewer gets |
|---|---|---|
| 0–60 | 0–2 | Already inside a readable product state. No logo. |
| 60–240 | 2–8 | The problem, in that same UI. |
| 240–480 | 8–16 | One state change, caused by a cursor or by data. |
| 480–660 | 16–22 | One proof. Hold it. |
| 660–780 | 22–26 | The claim, held 45–90 frames. |
| 780–900 | 26–30 | The product name and one line. Late. Smaller than the claim. |

Readable product UI covers at least half of these frames. A title card does not count as UI.

## UI decision

Use the full screen when the screen is the story and the type survives at final size.

Crop when the full screen is dense. The crop is the shot.

Capture a real interaction when behavior is more persuasive than a still.

Abstract the system when one screen cannot show the idea — and keep the abstraction faithful to how the product actually works.

Hybrid when the real UI earns trust and a motif carries the feeling. They share one coordinate system.

## Shot language that holds up

- A control at hero scale, with a cursor that has a reason to be there
- A component that enlarges into the detail that matters
- An action, then the product's response, as the next idea
- Data moving along a path the product really has
- Before and after in the same layout
- A sentence set like type, not like a subtitle track
- A chapter label used consistently, or no chrome at all

## Do not ship

- The entire dashboard at a glance-size
- Placeholder cards with generic icons
- A terminal that says nothing
- A wall of code
- Particles standing in for "AI"
- Selection chrome from a design tool, unless that tool is the product
- A feature list where a mechanism should be
- A type reel that shows the product for a few seconds and calls itself a launch
