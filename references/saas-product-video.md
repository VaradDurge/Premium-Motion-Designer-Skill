# SaaS/product video reference

## UI decision tree

Use full-screen UI when the UI itself is the product story.

Use focused UI crops when the full screen becomes dense.

Use interaction capture when motion/behavior is more persuasive than the static interface.

Use conceptual motion when the product's value is a system-level idea that would be hard to see in one screen.

Use a hybrid when credibility comes from real UI but emotional impact comes from a visual metaphor.

## Typical high-quality SaaS shot language

- interface enters as a physical object in a controlled space
- component enlarges into a hero detail
- cursor/action causes a visible system response
- data travels along an actual pipeline
- before/after state creates a clear contrast
- product UI becomes an environment rather than a screenshot
- real UI and typographic statements share one coordinate system

## Avoid

- full dashboard shown at tiny scale
- fake UI assembled just for aesthetics
- excessive glass panels
- generic terminal windows
- random code walls
- “AI = glowing particles” as the only concept
